4.   Multi-Type  RAG  Retrieval  System  
 
Six  distinct  retrieval  strategies  are  implemented.  The  system  selects  the  optimal  strategy  automatically  by

4.1   Dense  Retrieval  The  query  is  embedded  using  the  same  model  as  the  document  corpus  and  the  nearest  vectors  are  retrieved  by  
cosine

Qdrant.
 
This

4.2   Sparse  Retrieval  —  BM25  An  inverted  index  (implemented  via  elasticlunr)  applies  BM25  term-frequency  scoring.  This  complements  dense

4.3   Hybrid  Retrieval  (Default)  Dense  and  sparse  result  lists  are  merged  using  Reciprocal  Rank  Fusion  (k  =  60).  This  is  the  recommended  
default

4.4   Faceted  /  Filtered  Retrieval  Dense  or  hybrid  retrieval  is  applied  first,  then  filtered  by  metadata  predicates:  source  type,  date  range,  author,  or

7.2   Chunking  Strategy  Three  strategies  are  implemented.  The  intern  should  begin  with  paragraph-based  chunking,  measure  retrieval

Strategy Description Chunk  Size When  to  Use 
Paragraph-based(MVP  default) 
Split  at  paragraph  boundaries;  group  until  token  limit 
≤  512  tokens Best  balance  of  quality  and  speed 
Fixed-size Hard  split  every  N  tokens  with  configurable  overlap 
512  /  64  overlap Uniform  documents,  quick  indexing 
Semantic(future  phase) Embedding  similarity  identifies  natural  breakpoints 
Variable Highest  quality;  slow,  compute-heavy  
7.3   Embedding  Pipeline  —  Step  by  Step  1.  Fetch  new  or  modified  documents  from  the  sync  queue. 2.  Split  each  document  into  chunks  using  the  paragraph-based  strategy. 3.  Estimate  token  count;  ensure  no  chunk  exceeds  512  tokens. 4.  Send  chunks  to  Ollama  in  batches  of  32  for  embedding. 5.  Upsert  resulting  vectors  into  Qdrant  with  full  metadata  payload. 6.  Persist  chunk  text  and  references  in  SQLite. 7.  Update  sync_state  table  with  the  current  timestamp.

10.   Indexing  &  Sync  Pipeline  
 
10.1   End-to-End  Flow  8.  Fetch  —  Query  last-sync  timestamp;  pull  only  modified  documents  from  the  source  API  or  file  system. 9.  Transform  —  Normalise  to  the  unified  document  schema;  extract  and  clean  metadata. 10.  Chunk  —  Split  using  paragraph-based  strategy;  enforce  512-token  maximum  per  chunk. 11.  Embed  —  Send  chunks  to  Ollama  in  batches  of  32;  receive  768-d  float  arrays. 12.  Store  —  Upsert  vectors  into  Qdrant;  persist  chunk  text  and  metadata  in  SQLite. 13.  Commit  —  Update  sync_state  with  current  timestamp;  emit  progress  event  to  frontend.  
10.2   Error  Handling  
Failure  Scenario Recovery  Behaviour 
Network  unavailable Operations  queued  locally;  pipeline  resumes  automatically  when  connectivity  is  restored 
API  rate  limit  (429) Exponential  backoff  per  source;  Groq  fallback  to  Ollama  for  LLM  calls 
Malformed  document Skip  and  log;  proceed  with  remaining  documents;  alert  user  after  five  consecutive  failures 
Database  write  error Rollback  transaction;  retry  once;  surface  error  to  UI  if  second  attempt  fails

11.   RAG-Augmented  Generation  
 
After  retrieval,  the  LLM  synthesises  a  grounded  response  from  the  assembled  context  window.  Prompt  
engineering
 
ensures
 
consistent
 
citation,
 
appropriate

and

11.1   Context  Window  Assembly  
Block Content Token  Budget 
System  prompt Role  definition,  behaviour  rules,  user  profile  summary 
~300 
Retrieved  documents Top-K  chunks  grouped  by  source,  with  title  and  score 
~2  000 
Chat  history Last  five  conversation  turns  for  continuity ~500 
Current  context Current  timestamp,  upcoming  calendar  event  if  within  2  hours 
~100 
User  query Verbatim  user  input ~100  
11.2   System  Prompt  Design  The  system  prompt  establishes  the  assistant's  identity  and  constraints.  Key  directives: •  Ground  every  answer  in  the  retrieved  context;  never  introduce  information  from  outside  it. •  Cite  every  source  by  name  and  type  (e.g.  "Notion  —  Project  Brief,  14  May  2025"). •  If  the  context  is  insufficient,  say  so  explicitly  rather  than  speculate. •  Match  the  user's  language  register  (formal  vs.  conversational). •  For  calendar-related  queries,  treat  upcoming  events  with  higher  priority  than  past  ones.

15.   Implementation  Guidelines  
 
Area Guideline 
Chunking Start  with  paragraph-based.  Switch  to  semantic  only  if  retrieval  precision  is  below  60  %  on  the  test  set. 
Embedding  batching Use  batch_size  =  32  by  default.  Increase  to  64  if  a  discrete  GPU  is  detected  via  Ollama  stats. 
Qdrant  deployment Run  as  a  standalone  binary,  not  in  Docker.  Docker  adds  2–3×  latency  overhead  for  local  queries. 
OAuth  security Use  PKCE  (Proof  Key  for  Code  Exchange)  for  all  OAuth  flows.  Store  refresh  tokens  encrypted  via  sqlcipher. 
Rate  limiting Groq  allows  120  requests  /  min.  Implement  a  token-bucket  queue  in  Rust.  High-priority  user  queries  bypass  background  sync  jobs. 
Offline  behaviour All  search  (embedding  +  retrieval)  must  work  offline.  Queue  LLM  generation  requests  and  process  them  when  the  connection  is  restored. 
Latency  targets Embedding  <  100  ms  ·  Retrieval  <  50  ms  ·  LLM  generation  <  500  ms  ·  Total  end-to-end  <  2  s. 
Privacy No  document  content  is  sent  to  any  external  API  without  explicit  user  consent.  Embedding  vectors  are  safe  to  transmit  (not  reversible  to  plaintext). 
Testing  approach Write  integration  tests  for  the  full  pipeline  (ingest  →  chunk  →  embed  →  retrieve  →  generate)  using  a  fixed  50-document  corpus  with  known  ground-truth  answers.
